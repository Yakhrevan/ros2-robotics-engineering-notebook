# How to Maintain This Notebook

## Never copy a tutorial blindly

Write:
- what it means
- why it works
- what can fail
- what you observed

## Keep source links

Prefer:
1. official documentation
2. standards/specifications
3. official source code
4. peer-reviewed papers
5. high-quality books
6. community tutorials

## Version every experiment

Record:
- Ubuntu version
- ROS 2 distribution
- compiler
- DDS implementation
- Fast DDS/Cyclone version
- hardware
- network topology

## Separate facts from hypotheses

Use:

**Fact:** observed or documented behavior.

**Hypothesis:** what you currently think explains it.

Then test the hypothesis.

## Update stale links

ROS, DDS implementations and package APIs evolve. When a link changes, update the repository rather than silently relying on old material.
